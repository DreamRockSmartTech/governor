# The .governance/ tree — layout and ownership

The governance tree is plain files and degrades to `ls`/`cat` — but it is **not free-form**. Every
file and directory below has an owner, and the hooks enforce the boundaries. Drifting from this map
(inventing directories, hand-creating node files, editing generated views) produces commits the
pre-commit hook rejects.

## Layout

```
.governance/
├── INDEX.md                 GENERATED view — never edit; `governor index` regenerates
├── counters.json            machine-owned {NN} high-water counters — never edit
├── taxonomy.json            OPTIONAL repo override of node types / statuses / edge kinds
│                            (committed by humans as a deliberate vocabulary decision)
├── projects/                one node file per project        project-NN-<slug>.md
├── masterplans/             masterplan-NN-<slug>.md
├── epics/                   epic-NN-<slug>.md
├── workitems/               workitem-NN-<slug>.md
├── gates/                   gate-NN-<slug>.md
├── decisions/               decision-NN-<slug>.md
├── checks/                  gate proof scripts (executable .sh etc.) — committed, reviewable
└── hooks/                   POLICY hooks (committed, human-editable sh)
    └── _/                   ENGINE layer — generated by `governor init`, gitignored
```

Node files are created **only** by `governor new` — it owns id allocation, uid, owner stamping, edge
wiring, INDEX regeneration. There is no legal way to hand-create a node file.

## Ownership zones

| Zone                                 | Owner        | You may…                                              |
| ------------------------------------ | ------------ | ----------------------------------------------------- |
| Node frontmatter (id, edges, fields) | the CLI      | mutate via `new`/`set`/`edge`/`status` only           |
| Gate `status`                        | the machine  | nothing — `gate run`/`done` write it                  |
| Gate `criteria_check`                | fresh window | hand-author once, right after `new gate` (see cli.md) |
| `partial` on a gate                  | the human    | `set` it only on the user's explicit call             |
| Node prose body (below frontmatter)  | anyone       | free-edit on UNFROZEN nodes                           |
| `checks/` proof scripts              | anyone       | add/edit; they are governance periphery               |
| `hooks/` policy layer                | the team     | edit with the user's approval                         |
| `hooks/_/`, INDEX.md, counters.json  | generated    | never touch                                           |

## The freeze model (when prose stops being free)

A node **freezes** the moment another node relies on it through a reliance-declaring edge: `parent`
(a child derives from it), `blocked_by` (something waits on it), `supersedes` (it is a superseded
historical record). Derived from the graph — never a flag.

- Frozen = **meaning lock**: body, plain fields, structural edges immutable. To change a frozen
  node, supersede it (`governor new <type> --supersedes <id>`).
- `status` is exempt — workflow state, not meaning. A frozen epic still completes when its children
  are done.
- Weak annotation edges (`decisions`, `cites`) may still be added to a frozen node.
- The window for prose is therefore **at creation**: write `## Description` / `## Evidence` /
  `## Approach` into every node the moment you create it, before anything depends on it and before
  the commit that lands it. A bare frontmatter-only node defeats the review boundary.

## Prose body sections (what the human reviews)

- `## Description` — what this unit is, written for the reviewer.
- `## Evidence` — why it exists: the failing test, the finding, the user ruling.
- `## Approach` — decisions taken while implementing, including rejected alternatives and why.
- `## Session log` — short dated notes when work spans sessions.

Update prose as you go, not retroactively. If the node you need to annotate is frozen, put the notes
on the dependent workitem — or supersede.

## Never do (the drift fence)

- Never create or rename a file under `projects/ masterplans/ epics/ workitems/ gates/ decisions/`
  by hand — `governor new` only.
- Never edit YAML frontmatter by hand, except a fresh gate's `criteria_check` in its authoring
  window.
- Never edit `INDEX.md` or `counters.json`.
- Never invent new directories under `.governance/` — `checks/` is the place for proof scripts;
  everything else is node dirs, hooks, and the taxonomy override.
- Never renumber, reuse, or gap-fill `{NN}` ids — deletions leave permanent holes by design.
- Never flip `partial: true` on your own judgment — that decision belongs to the user, on record.
